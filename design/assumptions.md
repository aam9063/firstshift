# Assumptions: what the dataset and the design assume

- **Phase:** 2, problem framing (spec: `specs/02-problem-framing.md`; brief rule: "if a phase needs a number that is not here, it must be labeled as an assumption and added to `design/assumptions.md`").
- Each assumption names where it came from and what breaks if it is wrong.

| # | Assumption | Source | If wrong |
|---|---|---|---|
| A1 | The funnel dataset models every application as if its cohort had already matured to day 90, so late-stage counts (day30_active 234, day90_active 156, the 52.0% attrition they imply) are steady-state values, slightly optimistic for recent months. | `discovery/funnel-baseline.md`, full-maturation caveat | Retention baselines for the newest cohorts look better than reality; the pilot's day-30 and day-90 comparisons would overstate improvement. Mitigation: compare against control under the same caveat. |
| A2 | Scaling from the seeded dataset (15 restaurants, 6 months) to pilot scope (12 restaurants, 12 months) uses factor 1.6, so 4,500 applications become about 7,200 per year, 2,952 never contacted, 848 interview no-shows, 114 day-1 no-shows, 146 gone by day 30. | `discovery/pain-points.md`, shared derivations | Volume-dependent cost figures move proportionally; the ranking of pain points does not change, since all scale by the same factor. |
| A3 | A lost hire-equivalent costs one more cost per hire, 420 EUR (ads + HR time + manager time, the group's internal estimate), and this single rate is reused for every cost formula. | brief section 4 (rate); `discovery/pain-points.md` (reuse rule) | Cost-of-inaction figures are wrong, but the fix directions and the metric tree do not depend on them. |
| A4 | The conversion of never-contacted applicants is assumed at the funnel average, 7.2% applied-to-day-1, and is explicitly conservative because the uncontacted pool is enriched in the best weekend-shift profiles. | `discovery/pain-points.md` PP2; [T-jordi-08] | The never-contacted cost (89,460 EUR/yr) is understated, which strengthens rather than weakens the case. |
| A5 | Manager time on hiring has no EUR rate anywhere in the evidence, so it is carried in hours only (about 6 hours per week per restaurant, 3,744 hours per year across the pilots; 105 minutes observed on one Saturday). | brief section 4; ride-along counts; `discovery/pain-points.md` PP5 | Any EUR figure for manager time would be invented; the effort branch of the metric tree uses hours and per-hire instrumentation instead. |
| A6 | The seeded funnel is consistent with the brief baseline within stated tolerance (conversions within 5 percentage points, medians within 1.0 day): all six compared metrics are inside it. | `discovery/funnel-baseline.md`, comparison table | Funnel-derived baselines could not be trusted as the pilot's "before". |
| A7 | Shadow-path hiring (the managers' "maybes" pool, about 25 names per manager) is real but stays outside the modeled funnel, so real hiring volume per restaurant is higher than the counts suggest; its volume is treated as qualitative. | `discovery/funnel-baseline.md` caveats; [T-yolanda-14, T-yolanda-16]; [T-jordi-20] | Pilot-vs-control comparisons that ignore bench hires will misattribute fast, informal hires; the pilot therefore logs bench-originated hires explicitly. |
| A8 | Nómina360's 3-to-6-day employee creation includes human steps (document checks, registration), not just the API call, so the design attack is earlier documents and daily tracking, not only faster API writes. | [T-yolanda-20]; [T-sofia-04, T-sofia-16]; `discovery/systems-and-data.md` key finding | Offer-to-rota targets in the metric tree (7.5 to 3 days) are unreachable and H3 dies at its kill threshold. |
| A9 | The 3 pilot control restaurants are comparable to the 12 pilot units, per the signed scope. | brief section 6 | Attribution weakens further on top of the n = 3 limitation already stated in the metric tree. |
| A10 | HireDesk webhook delivery semantics (at-least-once vs at-most-once) and several auth details are unconfirmed and must be settled in Phase 2. | `discovery/systems-and-data.md` open items; interviewer notes [T-hugo] | Event intake may need de-duplication on our side; the idempotency rules (C-T5, C-T6) already assume duplicates. |
| A11 | The retained periods for rejected and benched candidates, and the exact Nómina360 employee-creation field list, are open questions the DPO and People Ops will set in Phase 2. | Interviewer notes [T-laura], [T-sofia] | Retention schedule (C-L4) and pre-collection payload design cannot be finalized until they answer. |
| A12 | Candidates will answer an automated first message if it names the restaurant, asks one concrete question and is fast; templated or vague messages risk the employer-brand screenshot the CPO fears. | [T-candidate-a-24], [T-candidate-b-22], [T-candidate-c-22]; [T-marta-18, T-marta-20] | The contacted-rate target holds but CSAT fails as a guardrail; message content becomes the design priority. |
